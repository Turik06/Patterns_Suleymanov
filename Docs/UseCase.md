# Варианты использования (UseCase)

## 1. Диаграмма прецедентов

```mermaid
flowchart LR
    User["Клиент / Внешний API"]
    Admin["Администратор"]
    Technologist["Технолог / Шеф-повар"]

    subgraph System ["Система"]
        direction TB

        subgraph Entities ["Управление сущностями (entity_service)"]
            UC_E1["Создать сущность (POST/PUT)"]
            UC_E2["Получить сущность по коду (GET)"]
            UC_E3["Обновить сущность (PATCH/POST)"]
            UC_E4["Удалить сущность с защитой связей (DELETE)"]
        end

        subgraph Reports ["Отчеты"]
            UC1["Сформировать отчет по типу и ID"]
            UC2["Сформировать отчет по умолчанию"]
        end

        subgraph Serialization ["Сериализация JSON"]
            UC3["Выгрузить все хранилище в JSON"]
            UC4["Выгрузить отдельную модель в JSON"]
        end

        subgraph Recipes ["Рецепты"]
            UC5["Рассчитать вес брутто и нетто"]
            UC6["Добавить полуфабрикат в рецепт"]
        end

        subgraph AdminGroup ["Управление и конфигурация"]
            UC7["Инициализация данных first_start"]
            UC8["Загрузка настроек settings.json через DTO"]
        end
    end

    User --> UC_E1
    User --> UC_E2
    User --> UC_E3
    User --> UC_E4

    User --> UC1
    User --> UC2
    User --> UC3
    User --> UC4

    Technologist --> UC5
    Technologist --> UC6

    Admin --> UC7
    Admin --> UC8
```

---

## 2. Описание ролей

* **Клиент / Внешний API:** запрашивает аналитические отчеты в нужных форматах (HTML, CSV, XML, TXT, MD, RTF), получает дампы сущностей в JSON, а также выполняет операции создания, чтения, модификации и удаления доменных сущностей через REST API и `entity_service`.
* **Технолог / Шеф-повар:** настраивает технологические карты, включает полуфабрикаты (составные рецепты) и контролирует расчет веса брутто и нетто.
* **Администратор:** отвечает за первичный запуск системы (`first_start()`) и управление файлом конфигурации `settings.json` через DTO-десериализацию.
